## 2. How to run it — verified by running it on 9 September 2026

Not copied from an older document. Every step below was executed today on this machine.

### 2.0 The environment does not survive a reboot

**It was down at the start of this session** — Docker not running, no emulator, no adb
ports — although the previous session left it up. Bringing it up is a **precondition, not a
step**. It is also worth doing early for its own sake: in one boot it has repeatedly
revealed blockers that eight sessions of source reading had missed.

### 2.1 JDK 17 — for Gradle only

```sh
java -version   # must be 17
```

This machine has Microsoft OpenJDK 17 at
`C:\Program Files\Microsoft\jdk-17.0.20.101-hotspot\` and `JAVA_HOME` is set to it.
**A newer JDK fails at CMake.** If Gradle is failing in a way that makes no sense, check
this first.

### 2.2 Docker, then the database

```sh
docker info --format "{{.ServerVersion}}"     # 29.3.1 today
pnpm db:start                                  # supabase --workdir services/api start
```

`db:start` may need a retry. It prints the local URLs and keys; the database is at
`postgresql://postgres:postgres@127.0.0.1:54322/postgres`.

**`verify:rollbacks` empties the public schema and leaves it that way.** After running it,
`pnpm db:reset` to reapply all 47 migrations.

### 2.3 A signable MR with a day in front of them

```sh
pnpm --filter @fieldforce/api seed:day
```

Prints the email of a demo MR (`demo-<hex>-mr@example.test`) whose password is in the
script. Creates three doctors — **Asha Deshpande, Vikram Rao, Meera Iyer** — three clinic
addresses, a beat plan and three visits.

The other three seeds do **not** produce a working day: `seed:mr` gives an account with
`doctors=0`, `seed:synthetic` gives 3,520 doctors whose accounts cannot sign in, and
`seed:reference` correctly refuses to invent content.

### 2.4 The emulator and the three adb ports

```sh
"$LOCALAPPDATA/Android/Sdk/emulator/emulator.exe" -avd Pixel_10 -no-snapshot-load
adb reverse tcp:54321 tcp:54321    # Supabase API
adb reverse tcp:54322 tcp:54322    # Postgres
adb reverse tcp:8081  tcp:8081     # Metro
```

**All three, after every emulator restart.** They do not persist.

### 2.5 Metro / Expo — use the hoisted CLI

```sh
node node_modules/@expo/cli/build/bin/cli start --port 8081
```

**The `pnpm --filter` form is broken** under `node-linker=hoisted`. Expo Go works with the
current dependency set; the repeated *"Expo Go will not work"* warning in older docs refers
to Transistorsoft background geolocation and PowerSync, **neither of which is in
`package.json` yet**. That warning will become true later. It is not true now.

### 2.6 Before `pnpm install`

**Stop every node process first.** Metro and a running emulator hold files open and the
install corrupts the store.

Node 24.14.1 and pnpm 9.15.9 are global, but the repo pins **pnpm 11.21.0** via
`packageManager` — use `corepack pnpm <cmd>`.

### 2.7 The native build, if you need an APK

`docs/gotchas.md` carries the two traps that cost a day each: the SDK's **CMake 3.22.1
cannot build this app on Windows** (its bundled `ninja` is not long-path aware; the fix is
`cmake;3.31.6` plus an explicit pin in the generated `build.gradle`, which is **lost on
every `expo prebuild`**), and **piping gradle into `tail` hides the failure** because the
exit code is `tail`'s.

## 6. The standing rules — day one

Drawn from `docs/gotchas.md`, which is where they actually live.

1. **Read for "passed", not for the absence of red.** A summary line that does not say
   `N passed (N)` is not a green run.
2. **A skipped suite is not a green one.** Two suites dead at their `beforeAll` with fifteen
   cases skipped has looked green more than once.
3. **Mutation-test everything, two-sided on table writes.** Break the thing the test
   protects and watch the test fail; then restore it and watch it pass.
4. **Every guard needs a positive control.** A guard that refuses everything passes its own
   negative test. `sync_entity_for_table` raises on an unknown table **and** resolves all
   four real ones.
5. **A guard that is not a trigger, a policy or a revoked grant is not a guard.** Enforcement
   lives in the database in this project, deliberately, so that a BYPASSRLS role cannot evade
   it and a second client cannot forget it.
6. **A written lesson is not a control.** Six worked examples in `gotchas.md`, two found on
   9 September. Convert the lesson into a guard with a positive control, or expect to meet
   it again. Three tests: *can it fail; does it name the right problem; does it have a
   positive control?*
7. **A boundary with one instance in the fixtures is untested by construction.** One sample
   row owned by one MR cannot prove another MR's samples are invisible.
8. **A branch unreachable only because of today's data is scheduled code, not dead code.**
   Ask what it would do when it runs, before the data changes.
9. **A search shaped like the answer you expect cannot find the answer you do not.** Search
   by *shape* — every `switch`, every lookup table, every if/else chain — not by the names
   you already know.
10. **Read the LIVE definition of a `create or replace` chain**, never the migration file
    that you think wrote it. `pg_get_functiondef` is the authority.
11. **A rollback file that has never been executed is a claim, not a rollback.** Two were
    broken today and both were found by running them.
12. **RUN THE APP.** See §7.

## 7. The characteristic defect

> **Unexercised code that looks exercised. Fourteen-plus confirmed instances.**

Complete, tested, correct modules that no caller reaches; branches fully handled and never
emitted; contract fields the server never sends. Every one of them passes review, passes
its tests, and does nothing.

Recent instances: `recordCheckIn`/`recordCheckOut` finished against the live RPC with the
screen calling the mock beside them (FE-W34); `sync/pull.ts` complete and called by nothing
(FE-W36); the `duplicate` verdict handled and emitted by nothing (FE-W35); the entire
rejection path in the queue UI (FE-W27).

**Expect it. It is the default state of this codebase, not an exception.**

**The only reliable detector has been trying to use the thing.** Not reading it, not
reviewing it, not testing it in isolation — running it. Eight sessions of source reading
missed a blocker that one emulator boot surfaced immediately. Three endpoint conversions
produced three contract-versus-schema defects, each found by the first real round trip.

> **Budget every remaining conversion as its conversion plus one defect.** That has been
> the rate, three times running.

## 12. Three things to say out loud

1. **The two halves of this product were built independently and have never agreed anywhere
   anyone looked.** Three endpoint conversions produced three contract-versus-schema
   defects. Today produced two more — a payload key that reached the client fixtures the day
   its column existed, and a contract that demanded provenance a geofence centre does not
   have. Budget each remaining conversion as its conversion **plus one defect**.

2. **Stopping is the correct outcome.** Four of the last eight sessions stopped early, and
   every one of those stops was worth more than the work it deferred — including two that
   stopped because a written instruction would have removed a compliance control. MR-11
   declined to add the `not_met` enum without its copy change, and that was right: the enum
   alone would have made the data distinguish what the screen still conflated.

3. **The blockers are not technical.** The engineering has been outrunning its estimates
   since August. See `docs/blocked-on-you.md`.
